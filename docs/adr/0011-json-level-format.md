# 0011. JSON level files with per-module component serializers

- **Status:** Accepted
- **Date:** 2026-11-09

## Context
Levels must be saved and loaded by the editor and the runtime, shared through version control, inspected and generated by AI agents over ACP, and kept forward-compatible as components are added by modules and plug-ins. The task brief requires documented formats, stable identities and migration tools.

## Decision
- **Text JSON** (`.alevel`), described in `docs/formats/level-v1.md` with a JSON Schema validated in CI.
- **Foundation JSON library** (parser + writer) instead of a third-party dependency: small, offline, with limits suited to untrusted input and fuzz-tested.
- **Entities by UUID**, parent by UUID, parents before children; roots sorted by UUID for stable diffs; floats in shortest round-trip form.
- **SerializerRegistry**: each module registers its components (world: Name, Transform; render: MeshInstance by mesh *name* via MeshRegistry; gameplay: Spin). World has no knowledge of specific components.
- **Unknown or invalid component data is preserved** (`UnknownComponents`) and re-saved, so no tool silently drops data it does not understand.
- **Explicit versioning** with step-wise migrations; newer files are refused.
- **Gameplay module** (layer 3) introduced so gameplay components such as Spin are shared by editor and runtime instead of being duplicated.

## Consequences
- Levels are readable and mergeable; large levels will be bigger and slower than a binary format. A binary cooked format for shipping builds can be added later without changing the source format.
- Every new component needs a serializer registration to be saved; components without one are skipped on save (they are runtime-only by definition).
- Undo snapshots also carry `UnknownComponents`, so editing a level with unknown data does not lose it.

## Alternatives considered
- **Binary format:** compact and fast but opaque to diff tools and AI agents.
- **nlohmann/json or similar:** well tested, but a large dependency for a small need, and its defaults (exceptions, no depth limit) fit untrusted input less well.
- **USD as the native level format:** planned as an interchange format (import/export), not as the editor's working file.
