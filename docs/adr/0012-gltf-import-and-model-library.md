# 0012. glTF 2.0 import and a content-path model library

- **Status:** Accepted
- **Date:** 2026-11-09

## Context
The editor needs real 3D models, not only cubes. Models come from other tools and from the internet, so files are untrusted input. Levels must refer to models in a way that survives restarts, other machines and version control, and AI agents must be able to read and write those references.

## Decision
- **glTF 2.0** (`.gltf` and `.glb`) is the first import format: open, royalty-free, widely exported (Blender, Maya, Substance, Sketchfab), and close to what the renderer draws.
- **Own importer** in a new **Assets module** (layer 1, `engine/assets`), on the foundation JSON parser. Every buffer view, accessor and index is bounds-checked; URIs may not use schemes, absolute paths or `..`; node graphs must be acyclic and single-parent; sizes are limited. Unsupported features (skins, morph targets, animations, other material channels) are skipped with a warning; required extensions and sparse accessors are refused. A 3,000-case mutation fuzz test runs in CI.
- **stb_image 2.30** (MIT / public domain), PNG and JPEG only, decodes textures. Dimensions are checked before decoding.
- **Renderer**: vertices gain UVs; `upload_texture()` uploads RGBA8 with mipmaps; one base colour texture per draw (descriptor set 0), white by default. Final colour = `MeshInstance::color` × texture.
- **ModelLibrary** (render module) owns a *content folder*. Models are addressed by content-relative paths with `/` separators. Each primitive and texture gets a stable name, `asset:<path>#mesh<m>.<p>` and `asset:<path>#texture<t>`, stored in level files. The `MeshRegistry` resolves unknown `asset:` names by importing the file, so opening a level loads the models it uses.
- **Spawning** a model creates one entity per glTF node (Name + Transform), so the hierarchy is visible and editable in the Outliner; nodes with several primitives get one child per primitive.
- **Sample content** is generated by `tools/make_sample_content.py` (deterministic, Apache-2.0), checked for freshness in CI and shipped as `Content/` next to the executables.

## Consequences
- Levels stay readable and AI-editable: references are plain strings naming a file and an index.
- Primitive indices tie a level to the structure of the glTF file; re-exporting a model with a different mesh order changes what a level shows. A content-hashed asset database with stable asset IDs (ROADMAP M2) will replace path-based names; `asset:` names will remain readable as a migration path.
- Models are imported at load time with no cache; large files load more slowly than a cooked format would.
- Textures are uploaded per file, not shared between files that embed the same image.

## Alternatives considered
- **cgltf / tinygltf:** mature, but cgltf leaves validation to the caller and tinygltf brings its own JSON library and exception-based errors. The format is small enough to validate ourselves with the parser we already fuzz.
- **Assimp:** many formats, but large, and its broad loaders are a bigger attack surface than one strict format.
- **FBX:** proprietary SDK licence; not compatible with a fully open toolchain.
- **One entity per model (no hierarchy):** simpler, but hides node structure that users and agents need to edit.
