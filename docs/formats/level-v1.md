# Level file format, version 1

**Extension:** `.alevel` · **Encoding:** UTF-8 JSON · **Schema:** [`protocols/level/schemas/level.schema.json`](../../protocols/level/schemas/level.schema.json) · **Implementation:** `engine/world/src/serialization.cpp`

Levels are plain JSON so they can be read, diffed, merged and generated by people, scripts and AI agents.

## Document

```json
{
  "format": "aether.level",
  "version": 1,
  "generator": "Aether Editor 0.7.0",
  "entities": [
    {
      "id": "6f1c2a4e-1b7d-4c3e-9a2f-0d4b5e6f7a8b",
      "parent": "…optional parent id…",
      "components": {
        "Name": { "value": "Lamp" },
        "Transform": { "position": [1, 0, -2], "rotation": [0, 0, 0, 1], "scale": [1, 1, 1] }
      }
    }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `format` | Always `"aether.level"`. |
| `version` | Format version (integer). This document describes version 1. |
| `generator` | Informational: the tool that wrote the file. |
| `entities[].id` | Entity UUID (RFC 9562 text form). Persistent identity; unique within the file. |
| `entities[].parent` | Optional UUID of the parent entity. |
| `entities[].components` | Component data keyed by component name (`kComponentName`). |

Ordering rules (the engine writes files this way; readers must not depend on more):
- Parents come before their children, and siblings appear in child order, so the hierarchy order round-trips.
- Root entities are sorted by UUID, which keeps diffs stable across saves.
- Floats are written with the fewest digits that read back as the same 32-bit value (`2.2`, not `2.200000047683716`).

## Built-in components

| Name | Fields | Module |
| --- | --- | --- |
| `Name` | `value`: string | world |
| `Transform` | `position`: [x,y,z] (m), `rotation`: quaternion [x,y,z,w], `scale`: [x,y,z]. Missing fields default to 0 / identity / 1. Rotation is normalised on load. | world |
| `MeshInstance` | `mesh`: mesh name, `color`: linear RGB; optional (omitted when default): `texture`, `metallic` (0..1, default 0), `roughness` (0..1, default 0.5), `emissive` (linear RGB), `normal_texture`, `metallic_roughness_texture` | render |
| `Light` | `type`: `directional` or `point`, `color`: linear RGB, `intensity`, `range` (point, metres), `shadows` (directional) | render |
| `Environment` | Sky and image-wide settings (first one in the level is used): `sky`, `horizon`, `ground` (linear RGB), `intensity`, `exposure`, `shadows`, `sky_visible` | render |
| `Collider` | `shape`: `box`, `sphere` or `capsule`; `half_extents` (box), `radius`, `half_height` (capsule), `offset`. Local space, scaled with the entity | simulation |
| `RigidBody` | `type`: `static`, `dynamic` or `kinematic`; `mass`, `friction`, `restitution`, `linear_damping`, `angular_damping`, `gravity_scale`; optional `linear_velocity`, `angular_velocity` | simulation |
| `Spin` | `axis`: [x,y,z], `speed`: radians per second | gameplay |

Mesh and texture names:
- `builtin:cube`: the unit cube; `builtin:sphere`: a sphere of radius 0.5; `builtin:white`: the default texture (written as an absent `texture`).
- `asset:<path>#mesh<m>.<p>`: primitive `p` of mesh `m` in a glTF file, `<path>` relative to the content folder with `/` separators, e.g. `asset:models/crate.glb#mesh0.0`.
- `asset:<path>#texture<t>`: texture `t` of that file as colour (sRGB); `asset:<path>#texture<t>.linear`: the same image as data, for normal and metallic-roughness maps.

Loading a level imports the models it names from the content folder. A name that cannot be resolved (missing file, wrong index) keeps the component data verbatim with a warning, like any invalid component.

Derived state (`GlobalTransform`) and hierarchy components (`Parent`, `Children`) are not stored; they are rebuilt from `parent` on load.

## Loading rules

The loader treats files as untrusted input:
- The JSON parser limits nesting depth (256) and size (256 MiB), rejects duplicate keys, invalid escapes and non-finite numbers, and reports errors with line and column.
- Structural errors (wrong format, bad or duplicate ids, wrong field types) reject the file and leave the world unchanged.
- A component the engine does not know, or whose data is invalid for its type, is **kept verbatim** and written back on save, with a warning. Levels made with plug-ins or newer engines do not lose data in older editors.
- A missing parent or a parent link that would form a cycle loads the entity as a root, with a warning.

## Versioning

- Additive changes (new optional fields, new components) do not change `version`.
- Any change that older readers would misinterpret increments `version` and adds a `LevelMigration` from the previous version. The loader upgrades older files step by step (`upgrade_level`); files newer than the engine are refused with a clear error rather than misread.
